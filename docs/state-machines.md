# Реализованные переходы

- Запись: создание `booked`; резерв посещения создаётся в той же транзакции. Отмена блокируется до согласования политик. Ручная очередь не повышает клиента автоматически.
- Посещение: `present` для начавшегося занятия; резерв становится `consumed`. Повторная отметка другим ключом отклоняется; коррекция/пропуск заблокированы.
- Платёж: вручную подтверждённая неизменяемая запись. Возврат — отдельная неизменяемая запись; проверяется остаток после возвратов и распределений. Онлайн-статусы отсутствуют.
- Перемещение одной картины: `dispatched → received`. Источник и назначение сохраняются. В пути картина недоступна для второй отправки. Приём меняет только локацию и состояние, собственник не меняется. Обратное движение создаётся новой отправкой с основанием; структурированная связь возврата ещё отсутствует.
- Outbox: неотправленное событие → внутреннее уведомление + `delivered_at` в одном SQL statement. Несколько worker используют `FOR UPDATE SKIP LOCKED`; уникальный ID уведомления исключает дубль. Доставки email/SMS нет.

Все команды, аудит, outbox и ответ идемпотентности фиксируются одной транзакцией. Мутации одной организации сериализуются advisory lock; это сознательное ограничение пропускной способности dev-версии. Финансовая история не имеет HTTP-команд UPDATE/DELETE.
