## Исправление, найденное при проверке

Первый чистый apply выявил гонку: migration Job подключался к PostgreSQL до его готовности и завершался с connection refused. Добавлено ожидание подключения к БД с общим таймаутом admin-команды 150 секунд. Повторяются только попытки подключения; ошибка SQL-миграции по-прежнему останавливает Job. Поведение ожидания покрыто unit-тестами. Повторная установка в новом namespace с пустым PVC успешно выполнила миграции и запустила все сервисы.

## Границы результата

Это проверка сборок и тестового запуска, не production-приёмка. Не выполнялись нагрузочные/OOM/HA/DR-тесты, проверка принудительного применения NetworkPolicy выбранным CNI, ARM64-сборки и удалённая публикация образов. Go race и govulncheck выполняются отдельными задачами CI. Общая БД и бизнес-библиотека по-прежнему ограничивают автономность сервисов; подробности в [архитектуре сервисов](microservices.md).

## Исправление security-проверки CI, 12 ноября 2026

В GitHub Actions на commit 604c235 тесты с race detector и go vet прошли, но govulncheck завершился ошибкой GO-2026-6859 в стандартной библиотеке Go 1.27.3. Источник: [backend job](https://github.com/faust-man/DELO/actions/runs/43288544626/job/131428335582). По отчёту сканера исправление доступно в Go 1.27.4.

CI и Docker builder переведены на Go 1.27.4, официальный Docker-образ зафиксирован новым digest. scripts/check.sh дополнен тем же govulncheck@v1.9.0, чтобы локальная проверка выявляла эту категорию ошибок до push. На Go 1.27.4 полный локальный check.sh прошёл: интеграционные Go-тесты на отдельной PostgreSQL, vet, govulncheck, 6 frontend-тестов, сборка и проверки манифестов. Сканер сообщает 0 уязвимостей в вызываемом коде; одна находка в требуемом модуле не достигается из кода приложения. Этот результат не означает отсутствие любых уязвимостей.

Дополнительно в Linux-контейнере Go 1.27.4 успешно выполнены go test -race -count=1 ./..., go vet ./... и govulncheck. Контрактные тесты читают docs/api/openapi.json: для проверки в контейнере каталог docs подключён read-only; первая попытка без него завершилась ошибкой отсутствующего файла.
