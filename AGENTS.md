# Работа в проекте ДЕЛО

ДЕЛО — CRM для художественных студий и небольших галерей. Система объединяет учёт занятий и картин. Сейчас в проекте есть проект ТЗ и документы по будущей реализации. Перед работой с кодом или инфраструктурой проверь фактическое дерево файлов.

## Где искать решения

- [Техническое задание](docs/technical-specification.md) определяет предметную область, роли и требования. Различай подтверждённые требования, предложения и вопросы с пометкой `___`. Заполняй неизвестные параметры только при наличии основания.
- [Архитектура](docs/architecture.md) описывает границы модулей и потоки данных. Go для backend и React для frontend заданы заказчиком. Модульный монолит, отдельные процессы API и worker, PostgreSQL и закрытое S3-совместимое хранилище составляют предложенную схему.
- [Развёртывание](docs/kubernetes.md) описывает обязательную платформу Kubernetes и предлагаемые профили сред. При изменении схемы сверяй локальный профиль, dev, staging и production. Оценки ресурсов и отказоустойчивости требуют проверки на стенде.
- [Приёмка и решения](docs/acceptance-and-decisions.md) содержит сценарии будущих проверок и открытые вопросы. Указывай результат проверки только после её выполнения.

## Как вносить и проверять изменения

- При изменении требования проследи его последствия для архитектуры, развёртывания и приёмки. Обнови затронутые документы вместе. Если источники расходятся, укажи конкретное расхождение и вынеси вопрос на согласование.
- Для функций CRM проверяй границы доступа по организации и роли. Для записи на занятия учитывай вместимость при одновременных запросах. Для платёжных сценариев проверяй повторную доставку событий на тестовых данных.
- Для кода запускай проверки затронутого компонента через доступные в проекте команды. Для документации сверяй ссылки, терминологию и статус решений. В результате перечисли выполненные проверки и оставшиеся ограничения.
- Пиши по-русски. Перед применением подходящего навыка прочитай его SKILL.md и сообщи о первом использовании. Рабочие заметки и результаты проверок сохраняй в work_notes/ по задачам. Решения, нужные команде, фиксируй в соответствующем документе docs/.
